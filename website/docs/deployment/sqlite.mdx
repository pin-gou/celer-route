# 部署：SQLite

SQLite 模式适合**单机部署、试用、PoC**。零外部依赖，启动即用。

## 适用场景

- 单节点 celer-route 实例
- 试用 / Demo / PoC
- 低写入量场景（日志 < 1000 QPS）
- 不想引入 PostgreSQL 的运维负担

要查看容器日志、停止容器、进入容器，分别执行：

```bash

docker stop celer-route            # 停止
docker start celer-route           # 再次启动
docker rm -f celer-route           # 删除容器（数据卷 ~/celer-route-data 不会被删）
docker exec -it celer-route sh     # 进入容器
```

## 配置示例

完整 `config.json`（位于 `${app-dir}/config.json`）：

```json
{
  "config_store": {
    "enabled": true,
    "type": "sqlite",
    "config": {
      "path": "/app/data/config.db"
    }
  },
  "logs_store": {
    "enabled": true,
    "type": "sqlite",
    "config": {
      "path": "/app/data/logs.db"
    }
  },
  "client": {
    "drop_excess_requests": false,
    "initial_pool_size": 5000,
    "enable_logging": true,
    "log_retention_days": 365
  },
  "framework": {
    "pricing": {
      "pricing_url": "https://getbifrost.ai/datasheet",
      "pricing_sync_interval": 86400
    }
  }
}
```

## 数据持久化

SQLite 是单文件数据库，**必须将数据目录挂载到宿主机**才能保证容器重启后数据不丢——上面的 `docker run` 已经通过 `-v ~/celer-route-data:/app/data` 做了这件事，数据落在宿主机的 `~/celer-route-data/` 下。

如需迁移到其他目录，把宿主机路径改掉即可，例如 `-v /srv/celer-route-data:/app/data`。容器内 `/app/data` 由镜像固定，**不要**改动。

文件权限：

```bash
# 容器内进程以 UID:GID=1000:0 运行，需要 GID 1000 才能写 /app/data
chown -R 1000:1000 ~/celer-route-data
```

## 备份

```bash
# 推荐：在线热备份（不锁库）
sqlite3 /app/data/config.db ".backup '/backup/config.db.$(date +%Y%m%d)'"
sqlite3 /app/data/logs.db   ".backup '/backup/logs.db.$(date +%Y%m%d)'"

# 容器场景
docker exec celer-route sqlite3 /app/data/config.db \
  ".backup '/backup/config.db.$(date +%Y%m%d)'"
```

详见 [数据存储后端 — 备份与恢复](../features/data-storage#备份与恢复)。

## 限制

- **单写者锁**：SQLite 同时只允许一个写入连接，高并发写入下会成为瓶颈
- **不支持水平扩展**：多副本部署 SQLite 会数据不一致，**仅用于单实例**
- **不适合作为共享存储**：NFS 上的 SQLite 性能与可靠性均不达生产标准
- 大数据量日志（> 10 GB）建议改用 PostgreSQL 或 ClickHouse

## 升级到 PostgreSQL

当单机部署无法满足需求时，可以平滑切换到 PostgreSQL：

1. 停止当前 celer-route 容器
2. 修改 `config.json` 中两个 store 的 `type` 为 `"postgres"` 并填写连接参数
3. 启动新后端，celer-route 会自动在新数据库中创建表结构
4. （如有需要）从 SQLite 备份恢复历史日志数据

详见 [数据存储后端 — PostgreSQL](../features/data-storage#postgresql)。
