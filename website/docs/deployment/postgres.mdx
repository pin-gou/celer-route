# 部署：PostgreSQL

PostgreSQL 模式适合**生产部署、跨节点 HA、高写入量场景**。celer-route 会启用
SQLite 不具备的能力：物化视图、GIN 索引、advisory lock 跨节点串行化等。

## 适用场景

- 生产部署 / 跨节点 HA
- 高写入量日志场景
- 大数据量（> 10 GB 日志）
- 需要 PostgreSQL 的运维工具链（监控、备份、HA 集群）

## 前置要求

:::caution 版本要求
celer-route 要求 **PostgreSQL 16 或更高版本**。启动时会硬性检查
`server_version_num >= 160000`，低于此版本将拒绝启动。
:::

```bash
# 检查版本
psql -h <host> -U <user> -c "SELECT current_setting('server_version_num');"
# 必须 >= 160000
```

**还需准备**：

- 一个可用的数据库（celer-route 会自动建表，但**不会创建数据库本身**）
- 数据库用户至少需要 `CREATE TABLE` / `CREATE INDEX` / `SELECT` / `INSERT` /
  `UPDATE` / `DELETE` 权限
- 推荐：在迁移期间给用户临时 `CREATE EXTENSION` 权限（celer-route 会尝试启用
  `pg_trgm`）

## 配置示例

完整 `config.json`：

```json
{
  "config_store": {
    "enabled": true,
    "type": "postgres",
    "config": {
      "host": "postgres",
      "port": "5432",
      "user": "pg_gateway",
      "password": "${POSTGRES_PASSWORD}",
      "db_name": "pg_gateway",
      "ssl_mode": "require",
      "max_idle_conns": 10,
      "max_open_conns": 100,
      "conn_max_lifetime": "1h",
      "conn_max_idle_time": "10m"
    }
  },
  "logs_store": {
    "enabled": true,
    "type": "postgres",
    "config": {
      "host": "postgres",
      "port": "5432",
      "user": "pg_gateway_logs",
      "password": "${POSTGRES_PASSWORD}",
      "db_name": "pg_gateway_logs",
      "ssl_mode": "require",
      "max_idle_conns": 10,
      "max_open_conns": 100,
      "conn_max_lifetime": "1h",
      "conn_max_idle_time": "10m"
    }
  }
}
```

:::tip 双库分离
建议 `config_store` 与 `logs_store` 走不同的数据库（甚至不同的 PostgreSQL 实例），
便于独立备份、独立的权限策略、独立扩缩容。
:::

## 网络与连通性

### Docker 网络（服务名 vs 固定 IP）

- **Docker Compose**：用服务名 `postgres` 作为 host 即可，Docker 内置 DNS 解析
- **Kubernetes**：用 Service 名 `postgres.default.svc.cluster.local`
- **CI 测试环境**（如 GitHub Actions + harden-runner）：因 DNS 被劫持，
  必须用 **固定 IP**（`tests/docker-compose.yml` 锁定了 `172.28.0.16`）

### SSL/TLS

生产环境强烈建议 `ssl_mode: "require"` 或 `"verify-full"`。若使用自签证书，
需额外配置 `sslrootcert` 路径。

## 调优

详见 [数据存储后端 — 连接池调优](../features/data-storage#连接池调优)。

**几个常见反模式**：

- `conn_max_lifetime` 设得过短（< 5 分钟）：会触发
  `SQLSTATE 0A000` "cached plan must not change result type"
- `max_open_conns` 设得过大（> PostgreSQL `max_connections`）：会导致排队
- `ssl_mode: "disable"` 在公网部署：明文传输密码与日志数据

### 动态密码（`password_command`）

支持通过外部命令动态获取密码（如 IAM 临时凭证、Vault 动态密钥）：

```json
{
  "host": "...",
  "user": "...",
  "password_command": "vault read -field=password secret/celer-route",
  "db_name": "..."
}
```

## 备份

```bash
# 逻辑备份（推荐）
pg_dump -h <host> -U pg_gateway -d pg_gateway \
  -F c -f pg_gateway_$(date +%Y%m%d).dump

# 恢复
pg_restore -h <host> -U pg_gateway -d pg_gateway \
  --clean --if-exists pg_gateway_20240101.dump
```

## 升级 celer-route

celer-route 的 PostgreSQL 实现采用**两池生命周期**以避免 pgx 缓存计划错误：

1. **启动时**：打开一个临时池跑 schema migration（DDL），完成后立即关闭
2. **运行时**：再打开一个全新的池用于查询流量

这意味着 celer-route 升级**不需要手动跑 migration**——只要新版本的代码包含必要的
migration，启动时会自动应用。建议在升级前备份数据库以防万一。

## 监控

celer-route 会记录以下 PostgreSQL 相关指标（接入 Prometheus 插件后可见）：

- 连接池使用率（`max_idle_conns` / `max_open_conns`）
- 物化视图刷新耗时
- GIN 索引构建状态
- Advisory lock 等待时长

关键慢查询（> 1s）也会写入日志。
