# Internationalization (i18n)

pg-gateway UI supports **English (en)** and **Simplified Chinese (zh-CN)** out of the box.

## Switching Languages

1. Click the **language icon** (🌐) at the bottom of the sidebar, next to the theme toggle
2. Select your preferred language from the dropdown
3. The UI updates immediately — no page reload required

Your language preference is saved in `localStorage` and persists across sessions. On first visit, pg-gateway automatically detects your browser's language setting and defaults to English if no match is found.

## Translating UI Components

The translation system covers:

- **Sidebar navigation** — all menu items
- **Dashboard** — page title, tab labels, filter labels
- **Model Providers** — provider list, status messages, empty states
- **Governance** — virtual keys table headers, status labels, empty states, model limits
- **Common UI** — action buttons (Save, Cancel, Delete, Install, Edit, Revoke, Restore, Activate, Deactivate, etc.), pagination, search, toast notifications, confirmation dialogs, state/status labels
- **Logs** — provider labels, request type labels, status labels, stat cards, column labels, empty states, filter labels
- **MCP Logs** — tool execution logs, stat cards, column labels, empty states, filter labels
- **MCP Gateway** — server management, client management, sessions, settings, server library
- **Routing Rules** — rule management, routing tree, complexity router tiers & boundaries
- **Skills Repository** — skill management, installation
- **Plugins** — plugin management
- **Observability** — observability settings
- **Webhooks** — webhook management
- **OAuth Grants** — authorization grant management
- **Model Catalog** — model browsing, capabilities, pricing
- **Configuration** — all 12 sub-routes (API Keys, Caching, Client Settings, Compatibility, Feature Flags, Large Payload, Logging, MCP Gateway, Observability, Performance Tuning, Pricing Config, Security), plus Custom Pricing and MCP Settings
- **NoPermissionView** — permission denied messages with i18n key support (`entityI18nKey` prop) for all 19+ workspace routes

## How to Contribute Translations

### Adding a New Language

1. Create a new directory under `ui/locales/<language-code>/` (e.g., `ui/locales/ja/`)
2. Copy all 7 namespace files from `ui/locales/en/` and translate the values
3. Register the new language in `ui/lib/i18n/config.ts`:
   - Add the import for the new locale's JSON files
   - Add the locale to the `resources` object
   - Add the locale code to the `SUPPORTED_LOCALES` array
   - Add the locale label to the `LOCALE_LABELS` object
4. Update the `SupportedLocale` type in `ui/lib/i18n/config.ts`
5. Run the tests to verify key completeness: `npx vitest run src/__tests__/i18n/`

### Updating Existing Translations

Edit the JSON files in `ui/locales/<language-code>/`. Ensure keys stay in sync between all language files — the key completeness test (`src/__tests__/i18n/key-completeness.test.ts`) enforces this in CI.

### Technical Architecture

- **Library**: [react-i18next](https://react.i18next.com/) + [i18next](https://www.i18next.com/)
- **Language detection**: `i18next-browser-languagedetector` (localStorage > navigator > en fallback)
- **Namespaces**: 7 namespaces (common, logs, config, governance, providers, dashboard, governance-ui)
- **Type safety**: Manual type definitions in `ui/lib/i18n/types.ts` provide autocompletion for `t()` calls
- **Namespaces**: 15 namespaces (common, logs, config, governance, providers, dashboard, governance-ui, mcp, routing, skills, plugins, observability, webhooks, oauth-grants, model-catalog)
- **Provider**: `I18nProvider` wraps the app in `clientLayout.tsx`
- **NoPermissionView**: Accepts an optional `entityI18nKey` prop that renders translated permission denied messages; falls back to `entity` string for backward compatibility

### Scope Notes

- **Dialog/Form fields** are out of scope for this i18n pass — they remain in English. These include form labels, input placeholders, dialog content, and field-level validation messages within modals and sheets.
- **Shared components** (e.g., prompt-repo components) remain in English to avoid breaking cross-component consistency.
- The `NoPermissionView` `entityI18nKey` prop enables per-route permission messages to be translated without modifying the shared component. All 19 workspace routes now use this pattern.
