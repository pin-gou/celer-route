# 接入 AI 客户端

安装并配置好 celer-route 后，下一步就是让日常使用的 LLM 客户端（编程 agent、桌面 Agent、IDE 扩展或任何 OpenAI 兼容工具）都走网关，不用每个工具单独申请各自的 API Key、也不用在各家控制台之间切换。

**「接入 AI 客户端」** 是 Web UI 里专门做这件事的页面：从网关实时拉取 `/v1/models`，按你勾选的子集与所选客户端，生成对应格式的可粘贴配置。整个过程是四步向导——选客户端与平台、配置接入端点、选择模型、生成配置——你不需要手写 JSON / TOML，也不需要记住每家客户端配置文件放在哪。

## 进入页面

- 完成[快速启动](../intro)（已部署 celer-route 并能调用一次 `chat/completions`）
- 左侧边栏 **模型 → 接入 AI 客户端**
- 或从首页 onboarding 完成后那张「接入 AI 客户端」卡片点进去

![接入 AI 客户端 — opencode（英文）](./agent-setup.assets/agent-setup-opencode.png)

## 流程概览

页面是一个四步向导，顶部有进度指示，底部是「上一步 / 下一步」。每一步改完不必等，点击**下一步**进入下一节；想回头改随时点进度条跳回，配置区会实时跟随刷新。

| 步骤 | 你要做什么 | 决定什么 |
|---|---|---|
| 选择客户端与平台 | 选 AI 客户端与操作系统 | 决定生成哪种格式的配置、配置文件路径用什么写法 |
| 配置接入端点 | 填 Base URL，选 API Key（必要时） | 决定客户端连哪里、用哪个 Key 鉴权 |
| 选择模型 | 勾选要暴露的模型、选默认模型 | 决定客户端里能看到哪些模型、默认走哪个 |
| 生成配置 | 复制文件内容、运行一键应用命令、或 curl 验证 | 把配置落到本机 |

## 第 1 步：选择客户端与平台

**操作系统**决定生成的配置文件路径与环境变量写法：macOS / Linux 用 `~/…`，bash / zsh 的 `export`；Windows 用 `%USERPROFILE%\…`，同时给 PowerShell 与 cmd 两种写法。系统会按当前访问设备的 UA 自动选中一个，可手动切换——切换会写进 URL 查询参数（`?platform=windows`），刷新或分享链接后保持不变。

**AI 客户端**下拉按 4 个分组列出所有内置接入：AI 编程 Agent、国内桌面 Agent、IDE 与扩展、通用 OpenAI 兼容。每个客户端对应一种配置格式与文件路径，下一步的「要暴露的模型」多选区是否出现也由这一步决定——会写模型清单进配置文件的客户端会出现多选，只写默认模型引用的不会。

## 第 2 步：配置接入端点

- **Base URL**：默认填当前访问的 origin（如 `http://localhost:8080`）。如要指向远端网关改这里即可，引擎会按所选客户端自动拼 `/v1` 或 `/anthropic`，**不要**手动在结尾追加。
- **API Key**：
  - 如果启用了推理鉴权（`enforce_auth_on_inference`），只能从「治理 → API Key」里已有的虚拟 Key 选一个；如果还没有，页面会提示你先去创建。
  - 如果鉴权关闭，页面会显示「推理鉴权已关闭」提示，生成的配置将省略 API Key 字段。
- **使用 Responses API（@ai-sdk/openai）而非 Chat API**（仅 opencode 出现）：勾上后 opencode 会走 `/v1/responses`；不勾默认走 `/v1/chat/completions`。仅在确认你的链路对 Responses API 完整兼容时勾选。

## 第 3 步：选择模型

模型候选项从已选 API Key 的视角实时拉自 `/v1/models`——选 API Key 后列表与默认模型候选项会按可见范围刷新。

- 部分客户端会出现「要暴露的模型」多选列表（带搜索框、「全选 / 清空」切换、刷新按钮）。默认全选；想给客户端少暴露一些就在这里裁剪。
- 不论选哪个客户端，都有一个「默认模型」下拉：从上面暴露的模型里挑一个当客户端启动时的默认。WorkBuddy / CodeBuddy 的默认模型会被排在清单首位。
- 这一步必须选出至少一个默认模型，否则下一步的「生成的配置」会提示「请至少选择一个模型以生成配置」。

新增 / 废弃模型后回到这里点**刷新**，列表会重新拉；记得重新生成配置并粘贴回客户端。

## 第 4 步：生成配置

「生成的配置」区按标签页组织，从左到右：

1. **一键应用**——一条自包含命令（macOS / Linux 是 bash，Windows 是 PowerShell）。粘贴到终端运行即可把配置并入对应位置：先备份原文件，再精准合并，只覆盖与 celer-route 相关的字段，其他 provider / 其他设置全部保留；原配置损坏时命令会中止而不是顶掉坏文件。运行完之后大多数客户端需要重启一次。
2. **配置文件**——按客户端生成的最终文件内容（`opencode.json`、`settings.json`、`config.toml`、`models.json` 等）。需要手工复制或在自动化流程中使用时复制这一段。
3. **环境变量**——把 `OPENAI_*` / `ANTHROPIC_*` 等导出即可走 celer-route，无需改动全局配置文件。适合临时调试、CI、远程开发。
4. **用 curl 测试**——一条即用请求，对你刚才选的 Base URL + API Key + 默认模型发起一次调用。返回 200 表示接入路径与默认模型都已生效；4xx / 5xx 会原样返回便于排查。

不需要的文件类型不会出现在标签页里——例如「Cursor / Trae / ZCode / 通义灵码」等只能在应用内配置的客户端不提供「一键应用」与配置文件标签页。

改完上面任意一步切回来，「生成的配置」会立即重渲，标签页里也始终反映最新选择。

## 注意事项

- **不会自动发现**：每次新增 / 废弃模型后，回到这一步刷新、重新生成、再粘贴到客户端
- **模型 ID 是 `provider/model`**：客户端侧需要的是模型目录里的完整 ID（如 `openai/gpt-4o`），不是显示名——选错了客户端会出现「模型不存在」
- **API Key 明文展示**：选中 Key 后页面会展示明文 `value` 仅本页可见，便于复制；不要截图外发
- **Responses API**：opencode 勾上后网关会走 `/v1/responses`；个别上游 provider 可能还没完整适配，遇到兼容问题关掉即可
- **路径与协议**：Trae 等客户端要求 Base URL 必须带完整 `/v1`；Claude Code 使用的 `ANTHROPIC_BASE_URL` 必须只填到 `/anthropic`，**不要**再追加 `/v1`——本向导生成的配置已经按各客户端约定处理

## 手动场景

不打开 UI 也能用——直接在终端跑 `celer-route-setup models`（不依赖网关在线），可用于 CI、远程机器、脚本化场景。
