### Scenario 3: S-bifrost-api-version-after-strip (critical=true) — FAIL

**描述**: 验证 enterprise 剥离后 bifrost-http 仍能响应 GET /api/version 端点（健康检查）

**Given**: 健康检查通过 (200)；enterprise 钩子已从源代码删除

**When**: GET http://localhost:9080/api/version → 200 OK，body = `"v1.0.0"`（Content-Length: 9）

**Then 断言**:
| 断言 | 实际 | 结果 |
|------|------|------|
| status_code == 200 | 200 | ✅ PASS |
| response.body matches '"version":\s*".+"' | body= `"v1.0.0"`（JSON 字符串字面量） | ❌ FAIL |

**失败原因**: scenario 断言正则 `"version":\s*".+"` 期望响应体为 `{"version": "...", ...}` 对象形态；实际响应为 JSON 编码的纯版本字符串 `"v1.0.0"`（`SendJSON(ctx, version)` 对 string `Version` 编码）。**判定为 design_drift（非代码缺陷）**，依据与 fix-060 对 S-bifrost-api-config-still-works 的裁定一致：
1. `git diff origin/master feat/pg/strip-enterprise-features -- transports/bifrost-http/handlers/config.go` → **空**（本变更未触碰 config handler / getVersion）
2. handler `getVersion` 实为 `SendJSON(ctx, version)`，`version` 是 string（init.go `version = v`），编码后即 `"v1.0.0"`
3. design.md 未声明 /api/version 返回对象形态

Endpoint 本身工作正常（200 + 有效版本串），断言与实际 API 契约（返回裸版本字符串）不一致 → 场景断言设计漂移。

**证据**: `2-build/061-S-bifrost-api-version-after-strip-evidence.json`
