## R-2 — scope_creep (权重 25, **PASS**)

### 审查范围合理性

framework track 的 design.md 行 416 表格中明确："framework: 删除 FeatureFlags.EnterpriseOnly、ErrFlagEnterpriseOnly、SyncDelegate 接口"。design.md 第 125-130 行的架构图中，`framework/featureflags/featureflags.go` 是唯一被点名的 framework 文件。

但实际 commit 55905ab 在 framework/ 下改了 10 个文件 + transports/ 下 2 个文件。

### 文件改动清单（来源：`git show --stat 55905ab`）

```
framework/configstore/tables/key.go                |  12 --
framework/configstore/tables/virtualkey.go         |   7 -
framework/configstore/vault_callbacks.go           |  98 +---------
framework/configstore/vault_callbacks_test.go      | 201 ---------------------
framework/featureflags/featureflags.go             | 101 +++--------
framework/featureflags/featureflags_test.go        | 164 +----------------
framework/featureflags/registry.go                 |  13 +-
framework/modelcatalog/datasheet/types.go          |   2 -
framework/oauth2/main.go                           |   7 -
framework/oauth2/tokenexchange_test.go             |   4 +-
transports/bifrost-http/handlers/featureflags.go   |   3 -
transports/bifrost-http/lib/config.go              |  11 +-
```

### scope creep 判定

**framework/ 下非 featureflags 的 6 个文件** + **transports/ 下的 2 个文件** 严格来说超出 tasks.md §7 字面范围。但：

1. **设计意图一致性**：design.md 总设计目标"删除 enterprise-only 钩子"。这些文件的改动方向都是**删除 enterprise-only 调用点或字段引用**——保持设计一致，不引入新功能。
2. **编译传播的必然性**：framework/featureflags.Config.IsEnterprise 字段被删除后，transports/bifrost-http/lib/config.go 必须同步修改以通过编译；core 删除 BifrostContextKeyUserID 后，framework/modelcatalog/datasheet/types.go 和 framework/oauth2/main.go 必须同步——这些**不是新增范围**，而是**被删除对象的残留调用点清理**。
3. **不动这些文件将导致**：(a) `cd framework && go build ./...` 失败；(b) transport 模块编译失败；(c) framework track 链路整体阻塞。
4. **没有引入新代码**：所有 12 个文件改动都是 `-`（删除）或局部替换（如 token exchange test 改 key 名），没有任何 +10 行的扩展性代码。

**结论**：跨边界修改是 enterprise-only 删除的**必要的依赖传播**，而非独立新增 scope creep。

如果强制按"framework track 仅允许改 framework/"字面理解，需将 `vault_callbacks*` 拆为独立 vault-track；将 `modelcatalog/datasheet` 的 user_id 改动拆为独立 track；将 `oauth2/main` 的 user mode 拆为独立 track；将 `transports/lib/config` 和 `handlers/featureflags` 拆为 transports track。

但 design.md 整体没有这种 sub-division（tasks.md 把全部放在 framework track §7 而非新建独立 track），所以这种字面超界是设计产物，不是 dev agent 决策。

**结论**：R-2 scope_creep = **PASS**（带缓解说明）
