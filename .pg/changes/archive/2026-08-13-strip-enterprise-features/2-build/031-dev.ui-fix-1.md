## 修复报告

### 问题
V-ui-3 FAIL: UI typecheck 因 configApi.ts 中 TIMEOUT_ERROR/FETCH_ERROR 返回形状违反 RTK FetchBaseQueryError 类型契约

### 摘要
Fixed

### 根因诊断
- **根因阶段**: verify（pre-existing 类型回归，非本 diff 引入）
- **根因位置**: ui/lib/store/apis/configApi.ts:92-98, 104-110
- **根因描述**: `getLatestRelease` 使用 `queryFn` 编写自定义查询函数，在超时/网络错误时返回 `{ status: "TIMEOUT_ERROR", error: "...", data: { error: { message: "..." } } }` 形状。RTK 的 `FetchBaseQueryError` 联合类型对 `"TIMEOUT_ERROR"` 和 `"FETCH_ERROR"` 分支要求 `data?: undefined`，但代码中提供了 `data: { error: { message: string } }`，导致 TS2322 类型不兼容。`npm run build` 通过是因为 Vite 的 esbuild 跳过完整类型检查。

### 修复内容
| 文件 | 变更 |
|------|------|
| ui/lib/store/apis/configApi.ts | 删除 TIMEOUT_ERROR 分支中的 `data: { error: { message: "Request timeout" } }` |
| ui/lib/store/apis/configApi.ts | 删除 FETCH_ERROR 分支中的 `data: { error: { message: "Network error" } }` |
