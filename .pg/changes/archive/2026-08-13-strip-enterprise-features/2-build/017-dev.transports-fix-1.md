Fixed

### 根因诊断
- **根因阶段**: dev（transports 路由层）
- **根因位置**: `transports/bifrost-http/handlers/ui.go:62-65`（UI catch-all 路由）+ 上轮 fix (015) 遗留的 4 处测试断言错误与 1 处死代码
- **根因描述**:
  1. **主根因（V-transports-2）**：`UIHandler.RegisterRoutes` 在**所有 API 路由之后**注册了 SPA catch-all `router.GET("/{filepath:*}")`。OSS 后端从未注册（且 strip 变更后更不应注册）enterprise 端点，因此 `/api/rbac` 等请求不会被任何 API 路由匹配，直接落入 UI handler 的 SPA 回退逻辑，返回 `index.html`（HTTP 200）。`s.Router.NotFound` 404 handler 永远不会被触达。
  2. **次要根因（单元测试阻断，015 fix 遗留）**：015 fix 在删除 enterprise-only 用户身份解析（`BifrostContextKeyUserID` 等）后，把 `mcpserver_auth_test.go` 的 4 处断言改写错误（标题说 "rejected" 却断言 `require.NoError`；"both/headers mode: user identity resolution is enterprise-only" 断言 NoError+global server，但 enforce=true 且无凭据时 OSS 正确拒绝）；并在 `mcpserver.go` 留下死代码 `if false {...}`；`genai_large_request_test.go` 使用被截断的 JSON body（期望 `ChatCompletionRequest`，而 gemini 路径永远不会返回该类型）；`integrations/utils.go` 的 `tryStreamLargeResponse` 与 015 文档化语义不一致（OSS 仍返回 true+500 而非落到正常响应路径）。
