### 根因分类契约（v1.1.0 / P1-3，强制）

修复前**必须**先判定根因类型，调 `pg-build-result` 时用 `--fix-root-cause` 标注。
编排器据此路由，分类错误会导致无效重跑或误终止：

| fix_root_cause | 含义 | 编排器行为 | 你要做的事 |
|----------------|------|-----------|-----------|
| `code_bug` | 代码缺陷（缺分支/契约错位/迁移漏字段） | fix 完成后**重跑 scenario-execute** | 改代码 → 跑测试 → record status=completed |
| `env_drift` | 环境漂移，**未修复** | **workflow_failed 终止**（重跑无意义） | 不改代码，record 标注根因；需人工重新 describe_env / 修环境 |
| `env_drift` + `--env-fix-applied` | 环境漂移，**已修复**（v3.14） | **重跑 scenario-execute** | 执行环境修复动作（restart/rebuild/deploy）→ record 附带 `--env-fix-applied` |
| `design_drift` | design.md 与实现契约不一致 | **workflow_failed 终止** | 不改代码，record 标注根因；需人工重跑 /2-pg-propose 修 design.md |

**判定要点**：
- 失败源于「代码该做的没做对」→ `code_bug`
- 失败源于「环境/依赖现状与 scenario 预期不符」且无法靠改本仓代码解决 → `env_drift`
- 失败源于「design.md 定义的契约本身有缺陷/与现状矛盾」→ `design_drift`
- 缺省（不传 `--fix-root-cause`）按 `code_bug` 处理

**env_fix_applied 判定（v3.14 修复 2）**：
- 环境漂移可通过本仓工具链自动修复（如 `pg-invoke-hook.py` 重启 role、
  重建并部署二进制、重新执行 prepare_env hook）→ 执行修复动作并验证生效后，
  record 时附带 `--fix-root-cause env_drift --env-fix-applied`
- 环境漂移需人工介入（如 describe_env 需重跑、外部依赖根本性损坏）→
  仅 record `--fix-root-cause env_drift`（不带 --env-fix-applied）

**design_drift 必须附带 `--design-drift` JSON**（累积到 drift.md 供审计）：
```
--design-drift '{{"phase":"scenario-fix","scenario_id":"<S-xxx>","location":"<design.md 章节/字段>","reason":"<契约偏移说明>","decision":"ACCEPT"}}'
```

### 修复策略指引

修复时按以下顺序定位根因：

1. **业务逻辑错误**：对照 design.md / scenario-<track>.yaml 的 When/Then 描述，看是否漏处理某个分支
2. **API 契约错误**：检查 Controller 注解、DTO 字段、序列化顺序
3. **前后端契约错位**：检查前端 API 调用与后端响应字段命名/类型
4. **数据库/迁移问题**：检查 Flyway 脚本、Entity 字段映射
5. **环境/配置问题**：仅当 design.md 明确要求新配置时才改，否则不碰
